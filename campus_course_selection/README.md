# 校园课程选课管理系统（文件系统版）

这是一个**不使用数据库**、基于 **Python + Pandas + Excel 文件** 的完整课程选课管理程序，对应题目要求。

## 一、功能对应

1. **课程目录查看**
   - 全部课程按“课程类别”分组。
   - 组内按“课程编号”升序排列。

2. **选课与退课**
   - 选课会增加课程已选人数。
   - 自动检查是否超过课程容量。
   - 退课会减少已选人数，并检查学生当前是否有足够选课数量。
   - 每一次操作写入不可随课程停开而删除的历史记录。
   - 历史记录字段包括：
     - 课程编号
     - 课程名称
     - 课程类别
     - 开课学院
     - 操作类型
     - 操作人（学号）
     - 操作时间
     - 操作数量

3. **课程停开**
   - 课程从当前课程目录删除。
   - 课程信息归档到 `stopped_courses`。
   - 原有 `records` 历史记录完全保留。

4. **选课记录查询**
   - 可按课程编号查询。
   - 可按学号查询。
   - 可按日期范围查询。
   - 支持“学期第一周周一 + 第几周”自动换算时间范围。
   - 上述条件可以组合。

5. **选课人次汇总**
   - 只统计“选课”操作，不扣除“退课”。
   - 可限定时间段和课程类别。
   - 可统计：
     - 全部课程总选课人次
     - 按课程统计
     - 按学院统计

## 二、文件结构

```text
campus_course_selection/
├── course_selection_manager.py
├── requirements.txt
├── README.md
└── data/
    └── course_selection.xlsx   # 第一次运行时自动生成
```

Excel 中包含四个工作表：

- `courses`：当前开设课程
- `records`：所有历史操作记录
- `enrollments`：学生当前选课状态
- `stopped_courses`：停开课程归档

## 三、运行方法

进入项目目录后：

```bash
pip install -r requirements.txt
python course_selection_manager.py
```

第一次运行会自动生成 `data/course_selection.xlsx`，并填入一些示例课程；示例课程初始已选人数均为 0，便于直接演示选课/退课。

## 四、设计说明

### 为什么历史记录里额外保存“课程类别”和“开课学院”？

题目要求课程停开后历史记录仍需用于后续教学分析。如果只在当前课程表里保存课程类别/学院，那么课程删除以后就无法再按类别或学院统计。因此每一次操作日志都会保存当时课程信息的快照。

### 为什么有 enrollments 工作表？

只有“课程已选人数”无法判断某个学生是否真的选过某门课，也就无法可靠地执行退课。因此单独保存当前学生-课程状态，同时历史过程全部保存在 records 中。

### 选课人次如何计算？

严格按照题目定义：

> 总选课人次 = 指定时间范围内所有“选课”记录的操作数量之和，不减去退课。

因此：
- 选课 1 次 + 退课 1 次 = 选课人次仍然是 1
- 选课数量 3 = 选课人次增加 3

## 五、答辩时可以强调的点

- 没有使用数据库，符合“基于文件系统”的限制。
- Excel 只是持久化文件，Pandas 完成筛选、排序、分组与汇总。
- 每次选退课都会立即落盘，因此关闭程序后数据仍存在。
- 停开课程采用“活动表删除 + 归档表保留”的方式。
- 历史日志是独立表，因此停课不会破坏历史分析。
- 写 Excel 时采用“先写临时文件，再原子替换”的方式，降低文件写坏的风险。
